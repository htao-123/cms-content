**时间：2026-03-06**

你问的 **“标准模式”**，其实在 AI Coding 里通常叫：

> **AI Task Spec / AI Prompt Standard**

目的只有一个：
让 AI **稳定理解任务 + 不乱改代码 + 不漏改后端 + 不引入新问题**。

很多团队（OpenAI / Anthropic / Cursor 团队内部）其实都在用类似结构。

我给你一套 **工程实践里最稳定的一种结构**。

---

# 一、AI Coding 标准 Prompt 结构（推荐）

标准结构通常是 **6 个部分**：

```
1 Problem
2 Context
3 Expected Behavior
4 Constraints
5 Implementation Guidance
6 Deliverables
```

这是目前 **最稳定的 AI coding prompt 模式**。

下面我详细解释。

---

# 二、1️⃣ Problem（问题）

描述 **真实问题**。

必须包含：

* 用户行为
* 触发步骤
* 结果

例子：

```
Problem

当用户点击【添加文件夹】，并选择一个包含约500个文件的文件夹后，
系统会扫描联系人。

在联系人列表页面点击【本页批量导入】时，
系统提示“导入失败”。

需要修复该问题。
```

好处：

AI可以 **复现问题**。

---

# 三、2️⃣ Context（上下文）

告诉 AI **系统是什么架构**。

例如：

```
Context

项目结构：

Frontend:
- jotmo-frontend (React)

Backend:
- jotmo-backend (Go)

Mobile:
- jotmo-mobile (Flutter)

联系人导入流程：

文件扫描
→ 联系人列表
→ 批量导入
→ 后端导入接口
```

好处：

避免 AI：

```
乱猜架构
```

---

# 四、3️⃣ Expected Behavior（期望行为）

说明 **修复后的结果**。

例子：

```
Expected Behavior

1. 当用户点击【本页批量导入】时
2. 系统应成功导入联系人
3. 如果导入失败，需要显示错误提示
4. 错误提示必须使用 dialog
5. 不允许使用 toast
```

好处：

AI知道：

```
什么叫修复成功
```

---

# 五、4️⃣ Constraints（约束）

这是 **最重要的一部分**。

防止 AI：

* 乱重构
* 只改前端
* 改错模块

例子：

```
Constraints

1. 不允许只修改前端逻辑
2. 必须检查后端接口是否正确
3. 不允许引入新的 UI 组件
4. 所有错误提示必须统一使用 dialog
5. 不允许破坏现有导入流程
```

好处：

AI不会：

```
乱写代码
```

---

# 六、5️⃣ Implementation Guidance（实现建议）

可选。

告诉 AI **优先思路**。

例子：

```
Implementation Guidance

优先检查：

1. 批量导入 API
2. 前端分页逻辑
3. 文件扫描数据结构

重点关注：

- 批量导入参数
- 文件数量限制
```

好处：

AI不会：

```
全项目乱搜
```

---

# 七、6️⃣ Deliverables（交付物）

定义 AI 输出。

例如：

```
Deliverables

1. 修复代码
2. 失败原因分析
3. 修改涉及的模块说明
4. 确认没有引入新的问题
```

好处：

AI不会只给你：

```
一段代码
```

---

# 八、完整示例

完整 prompt：

```
Problem

当用户点击【添加文件夹】并选择一个包含约500个文件的文件夹后，
系统会扫描联系人。

在联系人列表页面点击【本页批量导入】时，
系统提示“导入失败”。

需要修复该问题。


Context

Frontend:
jotmo-frontend (React)

Backend:
jotmo-backend (Go)

联系人导入流程：

文件扫描
→ 联系人列表
→ 批量导入
→ 后端导入 API


Expected Behavior

1. 本页批量导入应成功执行
2. 如果导入失败，需要显示错误提示
3. 错误提示必须使用 dialog


Constraints

1. 不允许只修改前端
2. 必须检查后端 API
3. 不允许引入新的 UI 组件


Deliverables

1. 修复代码
2. 问题原因分析
3. 修改模块说明
```

---

# 九、为什么这个模式最稳定

AI coding 最大问题是：

```
理解错误
```

这个结构解决了：

| 问题    | 解决           |
| ----- | ------------ |
| 任务不清晰 | Problem      |
| 系统不了解 | Context      |
| 结果不明确 | Expected     |
| 乱改代码  | Constraints  |
| 乱实现   | Guidance     |
| 输出混乱  | Deliverables |

---

# 十、真正高级团队会再加两个模块

如果是 **大型项目**，再加两个：

```
7 Architecture Check
8 Risk Assessment
```

例如：

```
Architecture Check

是否需要修改：

- 前端
- 后端
- 数据结构
```

---

# 十一、为什么你们现在的 prompt 有点乱

因为现在的 prompt 是：

```
口语模式
```

例如：

```
修复这个问题
顺便检查架构
再看看删除逻辑
```

AI容易：

```
理解偏差
```

---

# 十二、AI Coding 最强 Prompt 模式（我个人推荐）

真正顶级模式其实是：

```
Task Spec
+
Architecture Review
+
Implementation Plan
+
Code
```

也就是：

```
先分析
再写代码
```

成功率会从：

```
60% → 95%
```
