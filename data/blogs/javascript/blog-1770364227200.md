## JavaScript 的数据类型大盘点

在 JavaScript 的世界里，数据类型就像是搭建程序大厦的基石。掌握它们，不仅能让我们的代码更加稳健，也是应对前端面试的必备技能。那么，JavaScript 的数据类型有哪些，它们又有什么区别呢？

JavaScript 中有 8 种数据类型，其中 7 种为基本数据类型，包括`number`（数字）、`string`（字符串）、`boolean`（布尔）、`null`（空值）、`undefined`（未定义）、`symbol`（符号）和`bigint`（大整数） ；还有 1 种是引用类型`object`（对象），像`Array`（数组）、`Function`（函数）、`Date`（日期）等都属于`object`的派生类型。

基本数据类型的值是按值访问的，它们直接存储在栈内存中，占据固定大小的空间，且不可变。比如声明一个`number`类型的变量`let num = 5;`，数值`5`就直接保存在栈中。当进行赋值操作`let newNum = num;`时，会在栈中复制一份`5`给`newNum`，修改`newNum`的值不会影响到`num`。

引用类型则不同，它们是按引用访问。当创建一个引用类型的变量，如`let arr = [1, 2, 3];` ，栈中存储的是数组对象在堆内存中的地址引用，实际的数组数据`[1, 2, 3]`存放在堆内存里。如果再进行赋值`let newArr = arr;` ，`newArr`和`arr`指向堆中的同一个数组对象，通过`newArr`修改数组内容，`arr`也会跟着改变 。

## 数组判断大揭秘

在 JavaScript 编程中，判断一个变量是否为数组是一个常见的操作。但由于 JavaScript 的动态类型特性，这并不是一件简单的事情。下面，我们就来探讨一下判断 JavaScript 变量是否为数组的几种方法 。

### 使用`Array.isArray()`

`Array.isArray()`是 ES5 引入的一个静态方法，专门用于判断一个值是否为数组。它的使用非常简单，直接传入要判断的变量即可，返回值为布尔类型，`true`表示是数组，`false`表示不是数组。

```
let arr = [1, 2, 3];
let notArr = {name: '前端面试题'};
console.log(Array.isArray(arr)); // true
console.log(Array.isArray(notArr)); // false
```

这种方法的原理是直接检查值的内部 [[Class]] 标识 ，不依赖原型链或构造函数，所以它能准确地判断一个值是否为数组，并且不受对象原型或`constructor`属性的干扰。它还有一个很大的优势，就是可以跨全局执行环境安全使用，比如在`iframe`或多个窗口环境中，都能正确识别数组。

### 使用`Object.prototype.toString.call()`

每一个继承`Object`的对象都有`toString`方法，如果`toString`方法没有被重写，会返回`[Object type]`，其中`type`为对象的类型。但当除了`Object`类型的对象外，其他类型直接使用`toString`方法时，会直接返回内容的字符串，所以我们需要使用`call`或者`apply`方法来改变`toString`方法的执行上下文，从而得到准确的类型信息。

```
let arr = [1, 2, 3];
let notArr = {name: '前端面试题'};
console.log(Object.prototype.toString.call(arr) === '[object Array]'); // true
console.log(Object.prototype.toString.call(notArr) === '[object Array]'); // false
```

这种方法的原理是通过获取对象的内部`[[Class]]`属性来确定对象的类型 。它的优点是非常强大和通用，对于所有基本数据类型以及各种复杂的引用类型都能进行准确判断，即使是`null`和`undefined`也能正确识别。但它的语法相对繁琐，需要通过字符串比较来确定是否为数组。

### 使用`instanceof`

`instanceof`操作符用于检查一个对象是否是某个构造函数的实例，它的原理是检查对象的原型链中是否存在该构造函数的`prototype`。对于判断数组，就是检查对象的原型链上是否有`Array.prototype`。

```
let arr = [1, 2, 3];
let notArr = {name: '前端面试题'};
console.log(arr instanceof Array); // true
console.log(notArr instanceof Array); // false
```

`instanceof`的优点是语法简单，直观易懂 。不过它也有一些局限性，比如在多全局环境（如`iframe`）中可能会失效，因为不同全局环境下的`Array`构造函数是不同的，从一个框架传入另一个框架的数组，在目标框架中使用`instanceof`判断可能会返回`false`。而且如果对象的原型被修改，也可能导致误判或漏判。

## null 与 undefined 的微妙差异

在 JavaScript 的基本数据类型中，`null`和`undefined`都表示 “无值” 状态，这使得很多开发者对它们的区别感到困惑 。接下来，我们就深入剖析一下它们的不同之处。

### 定义与产生方式

`undefined`表示变量已声明但未初始化，或者函数无显式返回值、访问对象不存在属性、函数参数未传递时的默认值，它是 JavaScript 引擎自动赋予的。例如：

```
let a;
console.log(a); // undefined，变量声明未赋值
function doSomething() {}
console.log(doSomething()); // undefined，函数无返回值
let obj = {};
console.log(obj.unknownProperty); // undefined，访问不存在属性
function greet(name) {
  console.log(name);
}
greet(); // undefined，函数参数未传递
```

而`null`是一个表示 “空对象引用” 的值，由开发者主动赋值，用于明确表示 “此处不应有值” 。比如：

```
let user = null; // 初始化变量为空值
let element = document.getElementById('non-existent-element');
console.log(element); // null，未找到对应的DOM元素时返回null
```

### 类型与类型判断

`undefined`的类型就是`undefined`，使用`typeof`操作符检测`undefined`，返回`'undefined'` 。而`null`虽然从语义上表示空值，但使用`typeof`检测`null`时，却会返回`'object'`，这是 JavaScript 早期设计遗留的一个错误 。实际上，`null`是一种原始数据类型，并非对象类型 。在现代 JavaScript 中，更可靠的判断方式是使用严格相等运算符`===` 。例如：

```
let value1;
console.log(typeof value1); // 'undefined'
console.log(value1 === undefined); // true
let value2 = null;
console.log(typeof value2); // 'object'
console.log(value2 === null); // true
```

### 原型链表现

`null`不指向任何对象，它没有原型链，当访问`null`的属性或方法时，会返回`undefined` 。而`undefined`本身也没有原型链，访问`undefined`的属性或方法同样返回`undefined` 。例如：

```
let nullValue = null;
console.log(nullValue.anything); // undefined
let undefinedValue;
console.log(undefinedValue.anything); // undefined
```

### 类型转换与比较运算

在类型转换为布尔值时，`null`和`undefined`都会被转换为`false`，在条件判断中，它们的表现相同 。但在数值转换时，`null`会被转换为`0`，`undefined`会被转换为`NaN`（Not-a-Number） 。例如：

```
console.log(Boolean(null)); // false
console.log(Boolean(undefined)); // false
console.log(1 + null); // 1，null转换为0后进行加法运算
console.log(1 + undefined); // NaN，undefined转换为NaN后进行加法运算
```

在比较运算中，使用宽松相等运算符`==`时，`null`和`undefined`被认为是相等的；但使用严格相等运算符`===`时，由于它们类型不同，结果为不相等 。例如：

```
console.log(null == undefined); // true
console.log(null === undefined); // false
```

## typeof 与 instanceof 的深度剖析

在 JavaScript 的类型判断工具库中，`typeof`和`instanceof`是两个重要的成员，它们各自有着独特的用途和特点。

`typeof`是一个一元运算符，用于返回一个值的类型字符串 。它的使用非常简单，直接作用于变量或值。例如：

```
console.log(typeof 123); // "number"
console.log(typeof '前端面试'); // "string"
console.log(typeof true); // "boolean"
console.log(typeof undefined); // "undefined"
console.log(typeof Symbol()); // "symbol"
console.log(typeof BigInt(100)); // "bigint"
console.log(typeof function(){}); // "function"
console.log(typeof []); // "object"
console.log(typeof {}); // "object"
console.log(typeof null); // "object"，这是一个历史遗留问题
```

从上面的示例可以看出，`typeof`对于基本数据类型（除`null`外）的判断是准确的，对于函数也能准确识别 。但它存在一些局限性，比如无法准确区分数组、普通对象和`null`，都会返回`"object"` 。这是因为在 JavaScript 早期设计中，使用 32 位二进制存储值，前三位标识类型，`null`的二进制全为 0，与对象类型标识相同，导致了这个历史遗留问题 。在实际使用中，`typeof`适合快速判断一个变量是否为基本数据类型或函数 ，比如在函数参数检查中，可以快速判断参数类型是否符合预期 。

`instanceof`是一个二元运算符，用于判断一个对象是否是某个构造函数的实例，它的语法是`object instanceof Constructor` ，返回值为布尔类型 。其原理是沿着对象的原型链向上查找，看是否能找到构造函数的`prototype`属性 。例如：

```
let arr = [1, 2, 3];
console.log(arr instanceof Array); // true
console.log(arr instanceof Object); // true，因为Array继承自Object
function Person(name) {
  this.name = name;
}
let person = new Person('前端面试');
console.log(person instanceof Person); // true
console.log(person instanceof Object); // true
```

`instanceof`在判断对象的继承关系和具体类型时非常有用 。不过它也有局限性，它只能用于判断对象类型，对于基本数据类型无效 ，比如`123 instanceof Number`会返回`false` 。此外，在多全局环境（如`iframe`）中，由于不同全局环境的构造函数不同，可能会导致判断不准确 。

## 0.1 + 0.2 ≠ 0.3 之谜

在 JavaScript 的数字运算中，`0.1 + 0.2 !== 0.3` 这一现象常常让开发者感到困惑 。从直观上看，`0.1`与`0.2`相加，结果理应是`0.3`，但在 JavaScript 中，执行`console.log(0.1 + 0.2)`，得到的结果却是`0.30000000000000004` 。这背后的原因，要从 JavaScript 的数字存储机制说起。

JavaScript 遵循 IEEE 754 标准，使用 64 位双精度浮点数来存储数字 。在这种存储方式中，1 位用于符号位，11 位用于指数位，52 位用于尾数位 。当将十进制小数转换为二进制时，会出现无限循环的情况 。例如，`0.1`转换为二进制是`0.0001100110011001100110011001100110011001100110011001101`（无限循环） ，`0.2`转换为二进制是`0.0011001100110011001100110011001100110011001100110011010`（无限循环） 。由于 JavaScript 只能存储 52 位尾数，在存储过程中，这些无限循环的二进制小数会被截断，导致精度丢失 。

当进行`0.1 + 0.2`的运算时，实际是对截断后的二进制数进行相加 。相加后的结果再转换回十进制，就出现了偏差 。在二进制浮点数相加的过程中，小数位相加可能会导致小数位多出一位，又需要对第 53 位进行舍入操作，从而再次造成精度丢失 。这就是为什么`0.1 + 0.2`的结果不等于`0.3`，而是`0.30000000000000004` 。这种精度问题并非 JavaScript 独有，几乎所有遵循 IEEE 754 标准的编程语言都会遇到 。
