一、typeof null 的结果是什么？为什么？

这道题几乎是前端面试的“开胃菜”，但能说清底层原因的人并不多。

答案：typeof null → 'object'

底层原因（关键！）：

JavaScript 中所有值都会以二进制形式存储，不同数据类型对应固定的二进制“类型标识”：

- 数字类型（number）：二进制首位是 1

- 字符串类型（string）：二进制首位是 01

- 布尔类型（boolean）：二进制首位是 11

- 对象类型（object）：二进制首位是 000

而 null 的设计初衷是“表示一个空的对象引用”，它对应的二进制是 全0 —— 恰好和对象类型的标识（000）重合，因此 typeof 检测时，会误判 null 为 object 类型。

注意：这不是 null 本身属于对象类型，而是 JavaScript 语言设计初期的一个历史遗留 Bug，至今未修复（避免破坏现有代码兼容性）。

console.log(typeof null); // 'object'
console.log(null instanceof Object); // false —— 证明null不是对象

二、如何获取安全的 undefined？

很多新手不知道，undefined 其实是可以被“篡改”的，这就会导致我们获取到的 undefined 不是真正的“空值”。

先看问题：为什么需要“安全的 undefined”？

在 JavaScript 中，undefined 是一个 全局变量（不是关键字），因此我们可以人为修改它的值，比如：

// 篡改全局undefined
window.undefined = '我被篡改了';
console.log(undefined); // '我被篡改了' —— 此时undefined已经失效

如果代码中依赖 undefined 判断空值，一旦 undefined 被篡改，就会导致逻辑出错。

解决方案：使用 void 0 获取安全的 undefined

void 是 JavaScript 中的一个运算符，它的作用是：执行后面的表达式，无论表达式结果是什么，最终都返回原始的、未被篡改的 undefined。

因为 void 运算符的返回值是语言层面规定的“纯粹 undefined”，不受全局变量篡改的影响，因此 void 0 是获取安全 undefined 的最优方案（也可以写 void 1、void 'abc'，效果一致，但 void 0 最简洁）。

// 即使篡改了全局undefined，void 0 依然返回真正的undefined
window.undefined = '我被篡改了';
console.log(void 0); // undefined（安全）
console.log(void 1); // undefined（效果一样）

// 实际开发中判断空值（推荐写法）
function checkEmpty(val) {
  return val === void 0;
}

三、typeof NaN 的结果是什么？

这道题是典型的“反常识”题目，很多人看到 NaN（Not a Number），就会误以为它的类型是 string 或其他，其实不然。

答案：typeof NaN → 'number'

解析：

NaN 的全称是“Not a Number”，翻译过来是“非数字”，但它本质上是 number 类型中的一个特殊取值，用来表示“一个不是有效数字的数值”。

比如，0/0、Number('abc')、Math.sqrt(-1) 等操作，得到的结果都是 NaN —— 这些操作的目的是获取一个数字，但最终失败了，因此返回一个“无效的数字”，而这个“无效数字”依然属于 number 类型。

console.log(typeof NaN); // 'number'
console.log(NaN === NaN); // false —— 补充：NaN是唯一不等于自身的值
console.log(Number.isNaN(NaN)); // true

四、isNaN 和 Number.isNaN 函数有什么区别？

这两个函数都用来判断“是否是 NaN”，但用法和逻辑差异很大，也是面试中常考的细节题。

核心区别：是否会进行隐式类型转换

1. isNaN（全局函数）

逻辑：先将传入的参数 隐式转换为 number 类型，再判断转换后的值是否是 NaN。

问题：如果参数本身不是数字，但转换后是 NaN，isNaN 也会返回 true —— 这就导致它的判断不够“精准”。

// 示例1：参数是NaN，返回true（符合预期）
console.log(isNaN(NaN)); // true

// 示例2：参数是字符串'abc'，先转为number（结果是NaN），返回true（不符合预期）
console.log(isNaN('abc')); // true

// 示例3：参数是0/0，返回true（符合预期）
console.log(isNaN(0/0)); // true

2. Number.isNaN（ES6 新增，推荐使用）

逻辑：不进行隐式类型转换，直接判断传入的参数是否严格等于 NaN（只有参数本身是 NaN 时，才返回 true）。

优势：判断更精准，只针对“本身就是 NaN”的情况，避免了全局 isNaN 的误判问题。

// 示例1：参数是NaN，返回true（符合预期）
console.log(Number.isNaN(NaN)); // true

// 示例2：参数是字符串'abc'，不转类型，直接判断，返回false（符合预期）
console.log(Number.isNaN('abc')); // false

// 示例3：参数是0/0，返回true（符合预期）
console.log(Number.isNaN(0/0)); // true

// 示例4：参数是undefined，不转类型，返回false
console.log(Number.isNaN(undefined)); // false

五、== 操作符强制类型转换的规则是什么?

== 是 JavaScript 中的“松散相等”运算符，它的核心特点是：当两侧操作数类型不同时，会自动进行隐式类型转换，转换后再比较是否相等。

很多新手被 == 的转换规则搞晕，其实只要记住“先分类型，再按规则转换”，就能轻松掌握，具体规则分两类：

1. 两侧均为原始类型（string、number、boolean、null、undefined）

核心规则：优先将两侧都转换为 number 类型，再进行比较。

补充2个特殊情况（必记！）：

- null == undefined → true（语言规定的特殊相等，二者转换为 number 分别是 0 和 NaN，但不按转数字规则判断）

- null/undefined 与其他原始类型比较 → 均为 false（比如 null == 0 → false，undefined == '' → false）

// 示例1：string vs number → 转number后比较
console.log('123' == 123); // true（'123' → 123）

// 示例2：boolean vs number → 转number后比较（true→1，false→0）
console.log(true == 1); // true
console.log(false == 0); // true

// 示例3：null vs undefined → 特殊情况，返回true
console.log(null == undefined); // true

// 示例4：null vs 0 → 特殊情况，返回false
console.log(null == 0); // false

2. 一侧为引用类型，一侧为原始类型

核心规则：先将引用类型转换为原始类型，转换为原始类型后，再按照“原始类型转数字”的规则，将两侧转为 number 类型，最终比较相等性。

关键细节：引用类型转原始类型的优先级（必记）：

先调用 valueOf() 方法 → 若返回原始类型（string、number、boolean），则使用该值；若返回引用类型，则继续调用 toString() 方法 → 使用 toString() 返回的原始类型值。

// 示例1：array vs string → 数组先转原始类型
console.log([1,2] == '1,2'); 
// 步骤：[1,2].valueOf() → [1,2]（引用类型）→ 调用toString() → '1,2' → 两侧都是string，转number均为NaN → false

// 示例2：object vs number → 对象先转原始类型
const obj = { name: 'js' };
console.log(obj == '[object Object]');
// 步骤：obj.valueOf() → obj（引用类型）→ 调用toString() → '[object Object]' → 两侧都是string，相等 → true

// 示例3：function vs string → 函数先转原始类型
console.log(function(){} == 'function (){}');
// 步骤：function.valueOf() → 函数本身（引用类型）→ 调用toString() → 'function (){}' → 相等 → true

最后总结

以上5道题，都是前端基础中的“重点+易错点”，看似简单，却能反映出对 JS 底层逻辑的理解程度。

整理几个核心记忆点，方便快速回顾：

- typeof null → 'object'（历史 Bug，二进制全0误判）

- 安全 undefined → void 0（不受篡改影响）

- typeof NaN → 'number'（NaN 是无效数字，属于 number 类型）

- isNaN 转类型，Number.isNaN 不转类型（推荐用后者）

- == 转换：原始转数字，引用先转原始再转数字（记特殊情况）
